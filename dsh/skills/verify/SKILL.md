# Verify → вердикт по M/L-изменению

Финальный гейт после реализации: статус допущений из scope-контракта, находки линз с доказательством `file:line`, стоп-правило ×2, «что проверить на ревью». Ничего не правит.

## Как запускать

`verify.workflow.js` в этой папке — сгенерированная копия `claude/workflows/verify.workflow.js` из groundwork (`deepseek-flash` у каждого агента, линзы читаются из `~/.dsh/skills`). Руками не править: правка канона и `install.sh --dsh`.

Прочитать `verify.workflow.js` и вызвать инструмент `workflow`:

- `script` — дословное содержимое файла, целиком, без сокращений и пересказа. Скрипт не влезает в ответ — сказать об этом, а не урезать.
- `meta`:
  ```json
  { "name": "verify",
    "description": "Верификация M/L-изменения: diff → линзы → опровержение → сводка",
    "phases": [{ "title": "Diff" }, { "title": "Lenses" }, { "title": "Falsify" }, { "title": "Synthesize" }] }
  ```
- `args` — dsh не подставляет аргументы слэш-команды: взять их из текста сообщения пользователя после `/verify` и из scope-контракта этой сессии; недостающее не выдумывать, просто не передавать:
  - `cwd` — репозиторий; по умолчанию текущий;
  - `range` — git range; пусто = незакоммиченное против HEAD, на чистом дереве — HEAD против merge-base;
  - `assumptions` — допущения scope-контракта: `[{ "id": "ДОПУЩЕНИЕ-1", "text": "…" }]`;
  - `estimate` — оценка для стоп-правила: `{ "files": N, "loc": M }` или строка `"N files, M loc"`;
  - `scope` — цель и «не входит» из scope-контракта.

Саботаж тестов пишет только во временную копию (`git worktree` в `$TMPDIR`) — песочница `workspace-write` это разрешает; рабочее дерево не меняется.

## Что вернуть пользователю

1. **Вердикт** скрипта как есть: `OK`, `REVIEW_REQUIRED` или `BLOCKED`; `verified` — к какому HEAD и дереву он относится.
2. `stat`, размер и `stopRule` — сработало ли ×2 и почему.
3. **Находки**: скрипт нумерует их `V1…`, показывать как `НАХОДКА-N` с тем же номером (`V3` → `НАХОДКА-3`); severity, `file:line`, что не так, доказательство. Номера не менять.
4. **Допущения**: `CONFIRMED` / `UNVERIFIED` по каждому коду.
5. **Саботаж** и **coverage** — что не проверено (линза не отработала, тесты не запускались). Врать про полноту запрещено.
6. **«Что проверить на ревью»** — `reviewChecks`.

Последняя строка ответа — вердикт. Правки по находкам — отдельный шаг; после них — `/code-review`.
